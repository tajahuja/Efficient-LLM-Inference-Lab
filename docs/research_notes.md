# Research notes

## Hypotheses (registered before benchmark execution)

- H1: Increasing prompt length increases prefill latency and logical KV payload size for this fixed model and implementation.
- H2: Increasing batch size may raise aggregate generation throughput while raising amortized per-request latency.
- H3: Incremental KV reuse may reduce decode work compared with repeatedly evaluating the growing prefix in this implementation.
- H4: Smaller or lower-precision parameter/cache representations can reduce tensor payload, with possible runtime/output trade-offs. This run does not test H4.
- H5: The best configuration may differ between interactive latency and throughput workloads. This fixed-batch microbenchmark cannot establish a serving optimum.

These are hypotheses, not expected conclusions. Results are generated by `experiments/run_benchmarks.py` and summarized from the emitted machine-readable files; no numerical outcomes are pre-filled here.

## Relation to agent systems

Agent systems carry state between model calls, including conversation history, tool outputs, and runtime execution context. A model's KV state is distinct from an application's response cache. The Yandex Research article frames KV-state sharing and scheduling as a possible runtime design space. The current prototype measures only a narrow single-model compute path and does not modify cache views or coordinate agent streams.
